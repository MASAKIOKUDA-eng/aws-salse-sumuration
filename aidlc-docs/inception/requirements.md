# Requirements Analysis

## Intent

JAWS-UG Sales 支部 × 彩の国埼玉支部 English LT Night（2026-11-20）の登壇
「Developing a sales simulation application as a way to also verify cdkd's functionality」のために、
**AWS ソリューション営業の考え方を体験的に学べる** Web アプリを作り、その構築・デプロイを通して **cdkd の機能を検証する**。

## 背景：AWS ソリューション営業とは

アカウントマネージャーは、顧客の事業課題を理解し、SA・スペシャリスト・パートナーなどを集めて、
課題に合った構成・進め方・費用を提案し、顧客の意思決定を支援する。本アプリでは、これを「判断の連続」として体験させる。

## 機能要件

| ID | 要件 |
| --- | --- |
| FR-1 | 架空の顧客（4 社）からの引き合いと、その案件の条件（面談相手の立場・予算感・競合・時期）が乱数のシードから決まる |
| FR-2 | 利用者は次の判断を順に行う：事前調査（2）／同行メンバー（2）／質問（3）／課題の特定／サービス構成（1〜5）／進め方／費用の出し方／反論への対応（2）／クロージング |
| FR-3 | 予算感・競合・時期は最初は未確認とし、対応する質問・調査を選んだときだけ案件シートに表示する |
| FR-4 | 各判断に、営業マネージャーの視点の短い解説（コーチ）を表示する |
| FR-5 | サービス構成の画面で、構成の費用と予算感（確認済みの場合）を比べられる |
| FR-6 | 結果として、受注／失注・受注確度・年間利用見込み・4 軸の評価・ランク・工程ごとのフィードバック・模範的な進め方を表示する |
| FR-7 | 結果を成績表（DynamoDB）に記録できる（担当者名を付ける）。記録にはログインが必要 |
| FR-8 | 成績表（上位 10 件）・最近の商談・記録の詳細・自分の記録を閲覧できる。記録と同じ条件に挑戦できる |
| FR-9 | AWS 営業の基本（役割・ヒアリングの型・課題設定・提案・費用・反論・クロージング）を解説するページを持つ |
| FR-10 | サーバー側で結果を再計算し、改ざんされた点数を保存させない |
| FR-11 | 利用者はメールアドレスで自己登録・ログインできる（Cognito マネージドログイン） |

## 非機能要件

| ID | 要件 |
| --- | --- |
| NFR-1 コスト | 完全サーバーレス。常時起動のリソースを使わない。イベント規模では無料利用枠内に収める |
| NFR-2 デプロイ | AWS CDK で定義し、**cdkd** で高速にデプロイ／削除できる。通常の CDK CLI でもデプロイできる |
| NFR-3 配信 | CloudFront から配信し、S3 は非公開（OAC） |
| NFR-4 記録 | DynamoDB（オンデマンド）。イベント用途のため 90 日で TTL により自動削除 |
| NFR-5 セキュリティ | Lambda Function URL は IAM 認証、CloudFront（OAC）経由でのみ呼び出せる。入力値はサーバーで検証 |
| NFR-6 WAF | **使わない**（ADR-4）。イベント期間のみの公開で、固定費に見合わないため |
| NFR-7 利用環境 | スマートフォンでも操作できる。体験・閲覧はログイン不要 |
| NFR-8 見た目 | 「AI っぽさ」を避ける。グラデーション・影・角丸カード・絵文字を使わず、営業の帳票（案件シート・報告書）を模した見た目にする |
| NFR-9 正確さ | 架空の企業・人物であること、採点が学習用の簡略モデルであり AWS の公式見解ではないことを画面に明記する |

## 対象外

- 生成 AI による自由会話・自由回答の評価（全員が同じ条件で比べられること、採点理由の説明可能性、費用を優先）
- 独自ドメイン、ソーシャルログイン、WAF
